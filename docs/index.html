lockfile-diff

A lockfile diff is thousands of unreadable lines, so reviewers approve it blind. These are the five questions they would ask if the answers were cheap.

Every panel below is generated from a real diff, run by bin/lockfile-diff.js against real repositories and the public npm registry. Nothing here is illustrative.

How each question is answered

What is new, what changed major and what changed transitively come out of the lockfile itself. Directness is the one the lockfile buries: npm answers it from packages[""] and the install path, pnpm from the exact version each importer pins. A package can be a direct dependency at 7.x and simultaneously sit under some other package at 6.x, and those are two different rows.

What changed maintainer needs the registry: the maintainers list and the _npmUser who published each version. A package that changed hands between two versions is the highest-signal supply-chain warning the public registry offers. A lookup that fails is reported as UNKNOWN and never as "no maintainer change".

Install size delta is the sum of dist.unpackedSize. That is unpacked tarball size as the registry measured it at publish time, not node_modules on disk. A version with no size field makes the total a lower bound, and the count of those versions is printed next to it.
